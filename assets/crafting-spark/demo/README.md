# Crafting spark above an inventory slot

Pinned example: PixiJS 8.22.0, nixie-fx 0.1.20, Vite 6.4.4, Node.js 20 or newer.

## Run

```sh
npm ci
npm run vfx:validate
npm run vfx:export
npm run vfx:status
npm run dev
```

Open `http://127.0.0.1:5198/`. The exported files are included, so running the demo does not depend on the NixieFX editor or a product account.

`effects/crafting-spark.json` is authoring data generated by the official CLI and then configured by `configure-effect.mjs`. `public/vfx` is the compiled runtime bundle. Change the authoring JSON and export again. Do not patch compiled files.

## What to check

- Inspect at 0.10 seconds: 18 active particles above the iron slot, readable quantity labels.
- Repeat same event: ignored, with no restart.
- Reject craft: no new burst.
- Inspect at 0.80 seconds: zero active particles.
- Check 20 accepted events: each sample peaks at 18, drains to zero, and keeps one effect instance.
- Move and scale inventory: the next burst is positioned using the transformed slot anchor.
- Close inventory: the ticker stops, both layers hide, and craft controls disable. Reopen and accept a new event to restart the effect.

The fixed-step controls use a 120 Hz simulation clock while the regular ticker is stopped. They are lifecycle checks, not a device performance benchmark. The event buttons simulate game events; they do not implement a crafting server, modify inventory quantities, or test network delivery. The bounded set retains the last 32 event IDs only. A production application owns durable idempotency.

## Limits

This effect has no file textures, material graphs, trails, or sub-emitters. Its Pixi support report is `supported` with no warnings. It uses unlit additive compositing and a flat 2D projection. `render.shading = "lit"` requires the Three backend for lit shading. Pixi `depthWrite` uses its draw order / ink semantics rather than GPU depth-buffer writing. Neither setting is enabled here. Three.js rendering and mobile performance have not been tested.

The coordinate conversion runs on accepted events. Continuous movement during an already playing burst needs a separate policy. Closing the inventory pauses and hides the reused instance; final page teardown destroys the renderer and Pixi application. Backgrounding the tab pauses the ticker.

## Files

- `main.js`: runtime integration, local game-event controls, inspection UI and cleanup.
- `effects/crafting-spark.json`: complete normalized source effect.
- `configure-effect.mjs`: reproducible edits to generated defaults.
- `vfx-editor.prj`: editor project manifest.
- `public/vfx/manifest.json` and `public/vfx/effects/crafting-spark.json`: exported bundle.
- `package-lock.json`: dependency lock.
